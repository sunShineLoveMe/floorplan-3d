## 5. 实施顺序与约束

### A. 建立实际文案和问题清单

先用隔离上下文检查：首次无数据、已有英制工程、已有公制工程、中文语言偏好、旧格式回导、损坏保存和多窗口冲突。记录入口 / 状态 / 可见文案 / 可访问名称 / 下一步动作；沿用原生鼠标、键盘和可见表单。

只给已复现的问题分配缺陷 ID。问题表包含优先级、场景与输入、原生复现步骤、预期 / 实际、影响、建议、验收条件和证据。阻断主任务、静默数据变化或错误保存优先修复；遗漏说明、低可见性等按实际影响排后。每完成一项即复测。

### B. 引导应帮助做决定

- 首屏让用户知道示例房间可编辑，或怎样使用自己的净尺寸；不强迫重复创建默认房间。
- 复用现有入口。引导触发的替换仍经过既有确认 / 备份；不能为了演示跳过 T07 审查，或自动替换用户工程。
- 解释房间净宽 / 深 / 高、门窗所属墙与偏移、家具完整外廓、床垫预设与床架的区别，以及坐标是家具中心。未知高度保留未知。
- 解释 Wall snap 关闭仍保留单位网格；精确中心输入不吸附。通道 / 使用区是规划假设，冲突消失不表示实际开门、高度关系或法规已经验证。
- 保存说明覆盖“此浏览器 / 设备”、失败时 JSON 备份、下载后回导；JSON 项目恢复与图片 / PDF 参考图标定分开命名。
- 指引可跳过和重新打开，不遮挡关键字段或导致强制点击序列。纯帮助开关 / 阅读进度不改变工程、尺寸、updatedAt、编辑历史或保存修订；若需要记忆已关闭状态，按 UI 偏好独立存储，失败可继续使用。
- 不新增每次删除都确认的流程，不将示例材料人民币计价假换成 USD，不加入与任务无关的营销 / 付费入口。

### C. 文案与可访问性修复

沿用现有翻译机制，统一术语并核对实际渲染后的标签、title、placeholder、错误、状态和 aria；语言与显示单位独立，切语言不能改变项目单位、数值或名称。必要时做最小显示层修正，不新增翻译框架或名称数据迁移。

键盘应能完成核心的非拖动路径：选家具、输入尺寸 / 中心 / 旋转、编辑门窗、Undo / Redo、保存 / 下载与审查回导。核对 Tab 顺序、可见焦点、Enter / Space、Escape、模态关闭后焦点返回、隐藏抽屉不可聚焦；不要用 DOM click 或直接 store 写入掩盖入口不可操作。

错误应能与字段关联并保留输入；保存 / 冲突等状态应有适当的可访问反馈，避免每次预览都重复播报。核对文本与控件对比、色彩之外的冲突说明、放大与 reduced motion。工程检查通过不能表述为完整可访问性认证；没有执行的读屏 / 系统高对比度 / 真正浏览器缩放分别登记。
