## 3. BE-01：身份与数据基础（P0）

### BE-01-01：冻结数据与 API 契约

- [ ] 依赖：无。交付：云容器 v1、API / 错误契约、数据上限及迁移说明。
- 定义项目 UUID、可信用户 ID、`revision`、`expectedRevision`、`mutationId`、服务端时间、名称和删除状态；明确哪个字段由服务器管理。
- 云容器只保存领域数据与 asset ID；加载适配器恢复编辑器 v2。列出客户端未知字段和越权字段的拒绝 / 剔除规则，不依赖当前校验器保留未知字段的行为。
- 项目名称由元数据统一管理；恢复旧快照保留当前名称，避免历史正文反向覆盖重命名。草稿、拖拽预览、权限字段和 session 不进入正文。
- 分开设置正文、raster、源文件、项目数量和用户总存储上限；上限须配置化，经 BE-01-05 测量后冻结，不照搬原 8 MiB 请求上限。
- **验收**：用现有 v2、Umbria、含底图和畸形输入展示转换结果；毫米尺寸 / 高度无损，未知字段不能创建权限，错误可被前端区分为冲突、会话失效、配额和暂时故障。

### BE-01-02：建立 Worker 开发骨架

- 锁定稳定依赖；复用现有纯 JS 校验与 catalog，通过打包适配 Worker；将开发、测试、类型检查和打包命令写入后端 README。
- 静态发布目录只包含必要资源；API / 认证路径进入 Worker，其他静态请求直接服务。开发与生产资源绑定、秘密变量分离，提交 `.dev.vars.example`，不提交真实密钥。
- **验收**：本地启动、类型检查、最小 API 测试与打包通过；产物无文档、测试、云配置或秘密；当前前端仍能无登录打开本地工程。静态请求路由符合 [Static Assets 计费条件](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)。

### BE-01-03：D1 schema 与迁移

- [ ] 依赖：BE-01-01、BE-01-02。交付：统一迁移历史、索引与约束说明、初始化 / 升级验证。
- 认证表按选定 Better Auth 版本生成并审查；业务表包括项目、版本索引、资产、配额预留和 mutation 回执。快照正文放 R2。
- 约束用户归属、唯一 mutation、版本序号、删除状态及资产引用；查询按 owner / 项目分页并建立必要索引。业务 SQL 参数化。
- 认证与业务迁移统一管理；不在每次请求或生产启动时自动修改 schema。记录数据库迁移的向前修复 / 恢复办法。
- **验收**：空库初始化和已有库升级通过；非法归属 / 重复回执无法入库；项目列表不扫描其他用户正文。记录代表性操作的 D1 `rows_read` / `rows_written`。

### BE-01-04：Google 登录、会话与授权

- [ ] 依赖：BE-01-02、BE-01-03。交付：Better Auth / D1 接入、Google 登录 / 退出、后端授权函数和账号隔离测试。
- 实施时确认 Better Auth 当前稳定补丁版及 D1 适配，锁定依赖；配置开发 / 生产回调、可信 origin、Secure / HttpOnly cookie 和写请求的 CSRF 保护。[官方 Changelog](https://better-auth.com/changelog)
- 身份来自服务端会话；项目、版本、资产查询及修改均检查资源归属。客户端提交 `ownerId` / `role` 不能授权。
- 第一版不强迫本地工程登录；登录用于云空间。退出撤销当前会话，并停止该账号的保存队列；账号注销与删除数据的完整流程在 BE-04-01 验收。
- **验收**：未登录拒绝私有 API；A / B 真实账号不能互读 / 修改 / 删除项目和文件；伪造字段无效；退出后旧 session 失效；错误 origin 写请求被拒绝。只配置 OAuth 页面不算登录验收。

### BE-01-05：真实 Worker 最小保存验证

- [ ] 依赖：BE-01-01～BE-01-04。交付：开发环境贯通报告、CPU / 数据计量、并发及故障证据。
- 用 Umbria、含 raster 的云适配结果和最大允许项目贯通：可信会话 → 解析 / 校验 / hash → R2 不可变对象 → D1 条件更新 → 授权读取。
- 同 revision 并发只能一次成功；D1 条件 UPDATE 影响 0 行时，不写成功回执 / 版本索引。`batch()` 仅在语句实际失败时回滚，不能把“0 行更新”当 SQL 错误。[D1 batch 说明](https://developers.cloudflare.com/d1/worker-api/d1-database/)
- 注入 R2 失败、D1 失败、提交成功但响应丢失；验证无坏指针、无假成功、重试只提交一次。
- **验收**：保留真实环境请求结果、样本数量、CPU P95 / P99、错误数和 D1 行计量；分别记录首次与连续请求。免费 10 ms CPU 不稳定时调整配置 / 升级 Workers Paid，不削弱校验来凑额度。[Worker 限制](https://developers.cloudflare.com/workers/platform/limits/)
- **批次出口**：通过以上安全测试并冻结实测容量上限；本机 wall-clock 基准不能替代 Worker CPU。

## 4. BE-02：项目管理与云保存（P0）

### BE-02-01：私有项目 CRUD

- [ ] 依赖：BE-01。交付：项目列表、创建、复制、打开、重命名、软删除 API 与最小 UI。
- 列表返回元数据并分页；打开时获取当前正文。ID / owner / 时间由服务端生成；复制产生新 ID，服务器检查所有引用资产的权限。
- 写操作统一遵守幂等契约；项目保存和重命名 / 删除同时发生时，按 revision 或独立字段版本规则明确处理，不能互相覆盖。
- **验收**：A / B 项目完全隔离；重复创建 / 复制重试不产生多个项目；复制后编辑互不影响；名称与实际正文一致；删除项目不会继续自动保存。

### BE-02-02：正式保存与 mutation 回执

- [ ] 依赖：BE-01-05、BE-02-01。交付：生产用保存服务、条件 SQL、回执保留策略与故障测试。
- 每次提交冻结正文，使用新 R2 key；先确认对象写入成功，再在一个 D1 原子批次中提交 revision、版本引用及回执。后续 SQL 必须由同一成功 mutation 守卫，防止 0 行更新后继续写入。
- 回执绑定用户、项目、操作和请求 hash；同 ID 同请求返回原结果，同 ID 不同请求拒绝。并发重复请求同样只能提交一次。
- 定义回执保留期与客户端最大重试期；回执已过期时先重新同步状态，不能把旧请求自动作为新请求重放。
- **验收**：两浏览器同 revision 保存有明确冲突；响应丢失重试不增加 revision；数据库失败仅留下可清理孤儿；成功项目与全部保留版本始终指向存在的对象。

### BE-02-03：IndexedDB 草稿与恢复日志

- [ ] 依赖：BE-01-01、BE-01-04。交付：异步草稿服务、账号 / 项目分区与启动恢复流程。
- 云项目停止写全局 `floorplan-project-v2`；原未登录工程保持兼容。初始化先确定账号与分区，再暴露对应云草稿。
- 只捕获 `getCommittedProject()`，立即克隆 / 序列化冻结；IndexedDB 事务提交成功后才显示“已保存到本机”。持久化未确认请求的原始 payload / mutationId，以便重启重试。
- 记录本地序号、云基准 revision 和未同步状态；处理存储不可用 / 配额不足、多标签页和清理策略。退出后另一账号不能展示前账号草稿。
- **验收**：拖拽预览不入库；刷新 / 崩溃后可恢复未同步修改；旧应答不清除更新草稿；多标签页不会静默覆盖；磁盘写失败明确显示未保存并可导出。

### BE-02-04：异步切换与 Undo / Redo 隔离

- [ ] 依赖：BE-02-01、BE-02-03。交付：异步保护弹窗、项目 / 账号切换协调器及专门回归。
- 现有 `replaceProject()` 会把旧内容保留在 Undo 历史；云项目切换必须清空或按项目隔离历史，不复用普通“项目内替换”的语义。
- 修改保护流程以等待草稿落盘、导出及切换结果；Promise 失败不能被当作成功而关闭弹窗。
- 切换时处理拖拽事务、选择状态、表单、底图缓存和迟到的 API / 3D 加载结果；所有异步结果携带账号 / 项目 / 会话代次校验。
- **验收**：A 项目 → B 项目 → Undo 不会恢复 A 到 B；换账号不能看到前账号内容；慢网络、导出失败、迟到应答和中途退出均不会丢未保存工程。

### BE-02-05：保存队列、冲突与状态 UI

- [ ] 依赖：BE-02-02～BE-02-04。交付：按项目串行的保存协调器、状态 UI 和冲突处理入口。
- 本地先落盘，云端按内容变化、防抖及最长等待合并提交；避免每次 UI 通知都生成云版本。每项目只允许一个在途保存。
- 后续请求以已确认 revision 为基准；网络重试复用冻结请求。取消 fetch 不能视为取消服务器提交，重连后先核对回执 / 当前状态。
- UI 区分本机已保存、待同步、云端已保存、冲突、会话失效与配额不足。冲突支持保留本地副本 / 导出 / 查看云版本，禁止自动覆盖。
- **验收**：Chrome 编辑并保存，Safari 同账号恢复 Umbria 的 25 空间 / 33 墙 / 43 家具及毫米尺寸、高度；断网、过期会话、并发修改和连续拖拽后最终状态一致。

## 5. BE-03：文件与恢复

### BE-03-01：私有文件与 finalize（P0）

- [ ] 依赖：BE-01、BE-02-01。交付：授权上传 / 下载、配额预留、资产状态机与文件校验。
- 状态区分 pending / ready / 待清理；预留计入配额，包含在途上传，避免并发绕过限制。服务器核验实际大小、类型与 hash。
- 上传 staging 对象，finalize 后形成服务器控制的不可变 final 对象；重放上传凭证不能覆盖已被项目或历史引用的内容。

- **验收**：B 猜测 A 的 asset ID / key 不能下载；超额、伪 MIME、重复 finalize、凭证过期、上传中断和并发上传都符合契约；删除 / 换账号后不再签发访问凭证。

- 首次打开有网络时取得并缓存 raster；无法取得必要文件时明确报告工程不完整，不伪装为完全恢复。
- v2 导出内嵌底图，可在无登录 / 无网络 / URL 失效环境回导。保留现有文件字段与校验边界，不悄悄改变旧格式。

### BE-03-04：版本、回收站与安全清理（P1）

- [ ] 依赖：BE-02-02、BE-03-02。交付：版本列表 / 恢复、软删除 / 恢复、保留策略和分页清理任务。

## 6. BE-04：发布前验证（P1，公开试运营前必做）

### BE-04-01：配额、防滥用与账号生命周期

- [ ] 依赖：BE-02、BE-03。交付：账号 / IP / 操作限流、总容量配额、Turnstile、数据清理流程和权限矩阵。
- 覆盖创建、保存、上传、下载和认证入口；Turnstile 服务端校验，不能替代资源授权。限制 pending、版本和回收站实际占用。
- 检查所有 API 的越权、伪造字段及会话撤销；完成注销账号后停止写入、撤销会话、按声明保留期删除项目与文件的流程。
- **验收**：有脚本证明额度并发不可绕过；超限有稳定错误且本地可导出；注销账号不能继续使用旧 session，新账号不能取得残留资产。

### BE-04-02：用量、成本与故障观测

- [ ] 依赖：BE-01-05、BE-02-05。交付：结构化日志、用量视图、告警 / 人工检查办法及升级触发点。
- 记录 request ID、操作、revision / mutation 结果、耗时、错误、CPU 和 D1 行计量；不记录 session、签名 URL、完整图纸或正文。
- 以实测保存频率预测 Worker 请求 / CPU、D1 日写入 / 单库体积、R2 存储 / 操作；区分当前、历史、pending、回收站和备份占用。
- 按调研文档设置提前预警；Workers Paid 基础 $5/月和 R2 超额单独测算。告警不是硬性账单上限，免费日限额耗尽也不能当成自动扩容。
- **验收**：模拟会话失败、保存冲突、配额触顶和存储故障，能从 UI / request ID 定位结果；给出试运营预计月费及升级配置说明。

### BE-04-03：开发 / 生产部署与域名

- [ ] 依赖：BE-01、BE-04-01。交付：环境清单、发布 / 回退步骤、静态产物检查与 OAuth 回调配置。
- D1 / R2 / session secret / OAuth 配置按环境隔离；预览环境不得绑定生产用户数据。DNS、HTTPS、安全头、cookie、CORS 和资产路由在真实域名验证。
- 支持邮箱按需使用 Email Routing 转发来信；不把它当用户验证 / 找回密码邮件。需要事务邮件时另接 Email Sending 或外部服务。
- **验收**：开发环境和获授权的生产环境分别验证完整登录 / 保存 / 下载；静态产物无私密文件；回退应用时 schema 保持兼容。创建云资源和发布按当时用户授权执行，本清单本身未执行这些操作。

### BE-04-04：备份与联合恢复演练

- [ ] 依赖：BE-03-04。交付：D1 导出、独立 R2 备份、完整清单 / hash 与恢复报告。
- D1 Time Travel 不覆盖 R2；在隔离环境联合恢复数据库与引用对象，校验当前 / 历史 / 回收站文件完整性。
- R2 备份 / 删除宽限期须覆盖约定的数据库恢复窗口，避免数据库回到过去但对应文件已被清理。明确备份频率、保留期、权限及成本。
- 初始目标：每日独立备份，RPO ≤ 24 小时、RTO ≤ 4 小时；先用演练验证，未达到时记录实际值并修订承诺，不把 Time Travel 天数当作 RPO。[D1 恢复说明](https://developers.cloudflare.com/d1/reference/time-travel/)
- **验收**：新环境恢复后账号 / 项目归属、当前正文、历史底图和离线导出可用；报告实际恢复耗时及缺失项。演练不覆盖现有生产库。

### BE-04-05：浏览器、故障及发布验收

- [ ] 依赖：BE-02、BE-03、BE-04-01～BE-04-04。交付：自动化结果、原生浏览器报告、完整文件证据和剩余问题表。

- 故障矩阵覆盖两个账号、两个项目、两个标签页、迟到响应、离线、过期会话、CPU 超限、正文超限、配额、上传中断、D1 / R2 部分失败、恢复 / 清理竞态。
- **验收**：原生浏览器行为与导出文件均核对；本地自动化、远程 Cloudflare、手机实机及真实打印分别标记，未执行不标通过；现有未解决问题单独列出影响。
