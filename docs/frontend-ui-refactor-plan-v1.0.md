# 房间与家具布局工具：前端 UI 重构任务书

> 版本：v1.1（评审修订；保留原文件路径）  
> 日期：2026-10-01  
> 适用对象：产品负责人、前端开发、UI 设计师、执行改造的 Codex / 编码 Agent  
> 本期范围：编辑器的视觉体系、功能布局、控件呈现与必要的前端交互整理  
> 核心约束：保留现有编辑能力，不借 UI 重构重写业务引擎，不扩大为完整产品重建

## 0. 执行摘要

### 0.1 本次要做什么

将当前“顶部功能堆叠、左右面板信息混杂、参数感较强”的编辑器，改造成面向普通用户的、清晰克制的房间与家具布局工作区。

这次不是重新讨论商业模式，也不是增加更多装修功能。优先把已经实现的能力，放到合适的位置，用一致、易读的界面呈现出来。

**推荐实施顺序：**

**保留现状与建立基线 → 确认关键交互样稿 → 统一设计规范 → 重构整体布局 → 重排顶部与左右面板 → 整理画布控件 → 统一英文与尺寸显示 → 完成状态和回归验收 → 再做细节增强。**

### 0.2 已确定的设计方向

| 项目 | 本次采用的方向 |
|---|---|
| 整体气质 | 温暖、清晰、克制的消费级家居工具，不做企业管理后台或炫技科技大屏 |
| 页面底色 | 暖白或非常浅的中性色，避免所有区域使用同一层米黄色 |
| 工具面板 | 白色，主要依靠留白、细分隔线、轻微层次区分区域 |
| 文字 | 深石墨色为主，次要说明使用具有足够对比度的灰色 |
| 品牌强调色 | 本版统一采用深绿色 `#245C4B`，只用于主要操作、选中和焦点等必要位置 |
| 字体 | 优先复用已有 Inter；没有则使用系统无衬线字体，不为本次改造强制引入字体服务 |
| 数字 | 尺寸、面积等数值使用等宽数字特性；不把整个页面改成等宽字体 |
| 控件 | 常规输入框与按钮高度统一为 40px；独立图标按钮优先提供 44×44px 点击区域 |
| 卡片 | 适度圆角、弱化边框、减少重复阴影，不把所有内容都包成独立卡片 |
| 信息架构 | 顶部管理项目；左侧添加内容；中间编辑空间；右侧修改选中对象 |
| 首发对象 | 优先优化英文桌面编辑体验；语言与单位独立，不将所有欧美用户视为同一种习惯 |

**特别说明：用户最后提供的深色截图是“建议表”的截图，并不代表本次要改成深色主题。本次先做浅色主题。**

### 0.3 本文依据与适用边界

本文基于用户提供的当前编辑器截图、视觉建议表，以及本轮对话中已确认的改造方向。

2026-10-01 已完成代码层初步核查：当前为原生 ES Modules、SVG 与 Three.js；房间创建会替换当前方案；项目支持本地自动保存、JSON 导入导出和图片导出；2D 与 3D 已使用 ResizeObserver。当前分支为 `feat/project-data-t01`，提交为 `6af3c7d`。这些是代码核查结果，尚未进行本轮浏览器验收；执行 UI-000 时仍须重新核查分支和行为。文中的组件名是职责建议，不是已存在的文件名。

界面尺寸、色彩、布局断点和验收门槛是本项目的设计建议，不是“欧美用户已经验证喜欢”的研究结论。

## 1. 项目目标与不做事项

### 1.1 核心目标

本轮完成后，用户进入编辑器应能自然理解：

1. 在左侧添加房间结构或家具。
2. 在中央画布查看、选择和摆放。
3. 在右侧修改当前选中对象的属性。
4. 在顶部处理项目与已有文件操作，在画布附近调整视图。

同时，页面需要具备一致的字体、间距、颜色、控件尺寸、选中状态、禁用状态和错误反馈。

### 1.2 本轮允许修改

| 范围 | 允许修改的内容 |
|---|---|
| 样式层 | 颜色、字体、字号、间距、圆角、边框、阴影、图标尺寸、组件状态 |
| 布局层 | 顶部栏、左右侧栏、画布工具条、浮层、弹窗、滚动与收起方式 |
| 呈现层 | 英文界面文案、菜单分组、标签、帮助提示、信息显隐、数字展示格式 |
| UI 交互层 | 菜单展开、标签切换、面板收起、焦点管理、表单反馈、现有操作的入口迁移 |
| 轻量展示增强 | 利用现有家具目录做本地筛选；整理已有预览资源；显示层的尺寸格式统一 |
| 兼容性工作 | 防止侧栏布局导致画布缩放、点击坐标、滚动和已有快捷键回归 |

### 1.3 本轮不做

| 不做事项 | 处理原则 |
|---|---|
| 新的 AI 自动布局、户型识别或效果图生成功能 | 不加入本轮需求 |
| 重写 2D/3D 引擎、场景树或几何计算 | 保留现有实现，只接现有接口 |
| 改变家具真实尺寸、房间几何数据、坐标系或项目序列化格式 | 不因 UI 重构而修改 |
| 建立真实品牌商品库、购物联盟或商品抓取 | 不加入本轮需求 |
| 开发订阅、支付、账号、云同步或项目分享后端 | 不加入本轮需求 |
| 新增收费 PDF、专业报告、尺寸分析引擎 | 可以规划未来位置，不在本轮实现 |
| 全站官网、营销首页、定价页重做 | 当前只处理编辑器及其已有弹窗 |
| 强制迁移 React / Vue / 其他框架或新增完整 UI 库 | 沿用当前技术栈，必要依赖另行说明 |
| 重置用户现有项目、覆盖已有分支或删除历史能力 | 禁止作为“重构清理”顺带执行 |
| 深色模式、主题商店、任意拖拽停靠面板 | 暂缓，不影响本轮完成 |

**判断边界：凡是必须新增后台接口、改变项目数据结构、重写命中检测或重建算法才能完成的改进，单独记录，不默默塞入本轮 UI 任务。**

## 4. 新版编辑器的信息架构

### 4.1 四个区域的职责

| 区域 | 负责什么 | 不负责什么 |
|---|---|---|
| 顶部项目栏 | 项目名称、已有文件操作、撤销重做、真实保存状态、项目设置 | 不放日照滑块、墙体起终点、家具尺寸 |
| 左侧资源面板 | 房间列表、新建房间方案、门窗入口、家具分类与素材 | 不展示选中家具的完整属性或工程估价 |
| 中央画布 | 2D/3D 编辑、对象选择、视图控制、已有测量能力 | 不承载持久的大段教程或营销文案 |
| 右侧属性面板 | 当前房间、家具、墙、门、窗的已有可编辑属性 | 不默认混放全屋统计、人民币估价或内部 ID |

### 4.2 建议骨架

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Brand / Project name      [真实保存状态]   Undo  Redo   File  [现有主操作] │
├────────────────────┬────────────────────────────────┬────────────────────┤
│ Room | Furniture   │         2D Layout | 3D View     │ Selected object    │
│                    │                                │                    │
│ 当前标签的内容      │                                │ Size               │
│                    │                                │ Position / Rotation│
│ 房间或家具目录      │          房间编辑画布           │                    │
│                    │                                │ Appearance         │
│                    │                                │                    │
│                    │                                │ Object actions     │
│                    │      Measure   View   Fit      │                    │
└────────────────────┴────────────────────────────────┴────────────────────┘
```

说明：本版默认不额外叠加“图标导航窄轨 + 完整目录侧栏”两层结构，先使用单一左侧面板顶部标签，减少空间和交互复杂度。

### 4.3 布局尺寸建议

以下均为 CSS 像素，是起始设计值，不是要求每个设备机械照搬。

| 项目 | 建议值 | 说明 |
|---|---|---|
| 顶部项目栏 | 高 64px | 不允许工具组无限换行变成多排菜单墙 |
| 左侧面板 | 默认宽 280px | 宽屏可在 264～288px 内调整 |
| 右侧属性面板 | 默认宽 304px | 宽屏可在 288～320px 内调整 |
| 面板内边距 | 16px | 复杂弹窗可用 24px |
| 常规区块间距 | 24px | 紧密表单组内用 12～16px |
| 标题与内容间距 | 12px | 不依靠多层卡片建立层级 |
| 画布浮动工具距边缘 | 16px | 不能覆盖必需的对象操作手柄 |
| 主要工作画布参考宽度 | 尽量不低于 640px | 桌面编辑模式；不足时收起一个侧栏 |

以 1440px 宽视口为例，280px 左栏与 304px 右栏同时展开后，画布仍有约 856px 的水平空间，适合保留完整编辑结构。

### 4.4 侧栏展开规则

| 视口宽度 | 布局规则 |
|---|---|
| ≥ 1440px | 默认左右面板展开；无选择时保留右栏宽度，用户可主动收起 |
| 1200～1439px | 结合实际剩余画布宽度决定；不足 640px 时只展开一个主侧栏 |
| 1024～1199px | 默认只展开一个侧栏；另一个以可关闭抽屉呈现 |
| < 1024px | 不强行维持三栏；保留已有可用能力，入口折叠，避免遮挡关键按钮 |
| 触控小屏 | 后续增强，不承诺首版具备完整桌面建模体验，也不主动禁用原本可用能力 |

面板宽度与断点可以在验收时微调，但必须先保证画布和常用操作可用。

UI-005 样稿采用两栏展开条件“实际可用宽度 − 280 − 304 ≥ 640”，无其他边距时对应 1224px。1440/1280px 均可双栏；1024px 属性以覆盖抽屉显示，不改变画布容器宽度。抽屉打开会暂时遮住部分画布，可关闭恢复；不把容器宽度误写成完全可见宽度。

### 4.5 面板收起不能改变业务状态

收起 Furniture 面板不应删除待放置对象；收起属性面板不应取消对象；切换左侧标签不应重置房间或材质。

面板显示状态与场景选择状态必须区分。仅通过“卸载整个编辑器再挂载”的方式切换布局不可接受。

## 5. 设计规范

### 5.1 色彩 Token

| Token | 建议值 | 使用范围 |
|---|---|---|
| `--color-app-bg` | `#F6F7F4` | 应用整体浅背景 |
| `--color-surface` | `#FFFFFF` | 顶部栏、侧栏、弹窗 |
| `--color-surface-subtle` | `#F1F4F0` | 分组底色、弱化按钮、家具预览容器 |
| `--color-canvas-bg` | `#ECEFEB` | 画布周围背景；不得用大色块遮盖场景 |
| `--color-text-primary` | `#202823` | 标题、主要字段值 |
| `--color-text-secondary` | `#59645D` | 标签、辅助解释 |
| `--color-text-muted` | `#626D65` | 次要但仍需可读的文字 |
| `--color-border-subtle` | `#E0E5DF` | 非关键分隔线和装饰边界 |
| `--color-border-control` | `#7C877F` | 需要明确识别边界的输入控件 |
| `--color-brand` | `#245C4B` | 主要按钮、焦点和选中状态 |
| `--color-brand-hover` | `#1B473A` | 主要按钮悬停状态 |
| `--color-brand-soft` | `#EAF2EE` | 选中标签或卡片的浅背景 |
| `--color-danger` | `#B42318` | 删除、错误与破坏性动作 |

本版不同时保留深绿色主按钮、陶土橙选中按钮、其他高饱和强调色三套体系。现有家具模型本身的颜色不受此限制。

浅分隔线不应被当作所有输入框的唯一识别方式；需要辨识的控件边界、焦点和文字应单独检查对比度。

### 5.3 排版与信息层级

| 类型 | 建议字号 / 行高 | 字重 | 规则 |
|---|---|---|---|
| 项目名称 | 16px / 24px | 600 | 太长时截断，可查看完整名称 |
| 侧栏标题 | 16px / 24px | 600 | 例如 Furniture、Room properties |
| 分组标题 | 14px / 20px | 600 | 例如 Size、Appearance |
| 普通按钮与输入 | 14px / 20px | 400～500 | 优先清晰，不靠超细字体营造高级感 |
| 字段标签 | 13px / 20px | 500 | 不只使用 placeholder 充当标签 |
| 辅助信息 | 12px / 18px | 400 | 不承载唯一关键操作说明 |
| 重要尺寸值 | 14px / 20px | 500 | 使用等宽数字，不随位数变化跳动 |

避免把所有分类都写成密集的大写字母；主要操作使用自然的英文句式与一致的大小写风格。

### 5.4 按钮层级

| 层级 | 用法 | 视觉 |
|---|---|---|
| Primary | 当前页面最主要且真实可用的动作 | 深绿底、白字；同一区域不堆多个主按钮 |
| Secondary | 常用但非唯一主动作 | 白底、清晰边界或浅背景 |
| Ghost | 工具、轻量菜单、非主要操作 | 透明或弱背景，悬停与焦点明确 |
| Destructive | 删除对象、清空家具等 | 红色文字或确认弹窗中的红色按钮 |

`2D Layout / 3D View` 是状态切换，不与项目导出按钮争夺同一种大面积主按钮样式。

### 5.5 基础组件范围

先统一下列组件，再在业务区域复用：Button、IconButton、SegmentedControl、Tabs、Field、NumberField、Select、Popover、Dialog、Tooltip、Toast、EmptyState、PropertySection。

名称仅代表职责。当前项目不是组件框架时，可以用现有模板、函数或 CSS 类组织，不为形式统一而重写技术架构。

## 6. P0 详细任务

### UI-000｜当前分支、功能与页面基线核查

**目的：保护已经完成的功能，避免多个分支中的改动在重构时丢失。**

执行前记录当前分支、提交版本、工作区未提交修改和启动方式；确认哪些改动已经在当前分支中。不能仅凭截图或过往对话假定某个分支已经合并。

盘点顶部、左侧、右侧、画布和文件菜单中的真实动作。为每个动作记录现有处理函数或事件、依赖状态、拟迁移位置。

建立最小回归场景：一个房间、多个不同家具、至少一个门和一个窗；具体使用当前版本支持的能力，不伪造不存在的操作。保留项目数据副本与新旧截图。

**交付物：** 当前功能清单、入口映射、基线截图、回归场景、已知缺陷列表。

**验收：**

- [ ] 能明确区分现有能力、尚未实现能力与待核查项。
- [ ] 未覆盖用户未提交的修改，未执行破坏性分支清理。
- [ ] 确认现有保存、打开、导出、撤销的实际行为；没有用推测替代验证。
- [ ] 记录当前已有缺陷；不将其冒充为本轮新完成或新引入的问题。

### UI-005｜关键交互样稿与状态确认

在调整整体布局前提供可审查的样稿，覆盖无选择、选中家具、选中门窗，以及 1280px 与 1440px 宽度下的侧栏状态。样稿标出字段、操作位置、空状态、当前单位和替换方案提示；可以复用真实页面或线框，不要求新设计工具或依赖。

**验收：** 相同状态的左栏、画布与右栏职责明确；1280px 下有可执行的收起规则；关键操作不只靠颜色或图标猜测。样稿是开发依据，不能替代真实编辑器交付。

### UI-010｜设计 Token 与基础组件统一

**目的：先统一视觉语言，避免每个面板各改各的。**

按第 5 章建立基础变量，统一按钮、输入框、选项切换、卡片和弹窗。检查默认、hover、focus、selected、disabled、loading、error 状态。

采用现有图标资源或已有图标库，统一线宽与尺寸。不混用 emoji、彩色插画图标、不同风格的细线图标作为同一层工具。

**交付物：** 设计变量、基础组件样式、内部开发用状态展示页或对应组件样例。

**验收：**

- [ ] 同级控件高度与内边距一致，主要按钮采用统一深绿色。
- [ ] 新样式来自共享变量，而非每个区域重复硬编码。
- [ ] 禁用、选中、聚焦状态可以辨认；不只靠微小颜色差异。
- [ ] 圆角、阴影与边界克制，没有全页面卡片套卡片。
- [ ] 未新增不必要的大型依赖，未改变现有业务动作。

### UI-020｜编辑器整体布局重构

**目的：把页面从“功能堆叠”变成职责明确的工作区。**

实现顶部项目栏、左侧资源面板、中央画布、右侧属性面板。左右面板内容独立滚动；页面本身不要因家具目录过长产生第二层横向滚动。

默认宽度按第 4 章实施。宽屏右栏不随选择或取消选择自动展开、收起，以免画布反复跳动；无选择时显示轻量提示与房间设置入口。窄屏由用户打开可关闭抽屉。

画布容器尺寸变化必须通过现有渲染机制正确同步，包括实际渲染尺寸、相机宽高比、2D 缩放和坐标命中。不要仅改 CSS 拉伸画面。

**交付物：** 新编辑器布局与侧栏收起行为。

**验收：**

- [ ] 在 1440×900 与 1280×800 视口可正常使用，没有工具挤出屏幕。
- [ ] 面板展开 / 收起后场景比例正确，点击位置与对象位置一致。
- [ ] 面板滚动不会意外触发画布缩放；画布拖拽不会变成页面滚动。
- [ ] 不因布局切换重新创建整个场景或丢失选中对象、家具位置。
- [ ] 低高度窗口中关键按钮仍可到达，不能被固定底栏永久挡住。

### UI-030｜顶部项目栏与菜单重排

**目的：顶部只处理项目级动作，不再承载所有编辑细节。**

左侧显示真实品牌或现有项目名称，不臆造新品牌。中间或靠右放撤销、重做。文件菜单集中保留已有的新建、打开、保存、导出等能力。

保存状态仅在有真实事件可依据时显示。仅有本地保存就明确表达本地；尚无可靠保存状态时，宁可不显示状态徽标。

将日照、灯光、墙体高度、相机角度等迁到画布对应设置；语言、单位放入简洁设置入口。全屏属于工作区显示操作，不与主要业务动作同等强调。

**主操作按钮的条件规则：** 若已有稳定可用的导出，显示 `Export` 或与实际结果相符的 `Export plan`；只有项目文件保存时应使用准确名称。没有导出能力时不做一个伪造的绿色导出按钮，也不补收费页面。

**验收：**

- [ ] 顶栏在常规桌面宽度保持一行，低频功能进入菜单而非不断换行。
- [ ] 项目名过长不会把按钮推到屏幕外。
- [ ] 撤销 / 重做与原有历史行为一致，不可用时有真实禁用状态。
- [ ] 保存和导出文案与实际能力一致，没有“假 Saved”“假云同步”。
- [ ] 原有重要动作均能在新位置找到。

### UI-040｜左侧 Room / Furniture 面板整理

**目的：左侧只回答“我要添加或切换什么”。**

顶部使用 `Room` 与 `Furniture` 两个标签。Room 中承载房间列表、新建房间方案和已有门窗入口；Furniture 中承载家具分类与家具卡片。

家具卡片先复用现有图标或缩略图，但统一预览容器比例、内边距、名称和尺寸的排布。优先两列卡片；宽度不足时切换一列，不挤成无法阅读的窄块。

卡片信息顺序：预览 → 名称 → 简短尺寸摘要。完整尺寸与细节进入属性区。尺寸摘要必须包含明确的单位和维度含义，不能省到只剩无解释的数字。

只有当前已有自定义家具能力时，保留醒目的 `Add custom furniture`；否则不新造入口。搜索增强作为 UI-110，P0 不被新搜索功能拖住。

**验收：**

- [ ] 房间切换与家具选择不混在同一连续列表里。
- [ ] 常见名称可读，复杂分数字符串不挤满卡片。
- [ ] 卡片保持与现有家具数据关联，不误改模型尺寸或 ID。
- [ ] 点击和拖拽等原有添加方式仍可用；标签切换不会丢失场景。
- [ ] 分类、名称过长和无资源状态均有合理显示。

### UI-050｜右侧上下文属性面板

**目的：选中什么，就修改什么。**

通过当前应用已经存在的选择状态展示对应面板，禁止为了面板独立维护第二套家具实体数据。

| 当前选中状态 | 右侧主要内容 |
|---|---|
| 无选择 | 宽屏保持右栏宽度，显示轻量提示与已有房间设置入口；窄屏按抽屉规则 |
| 房间 | 名称、已有净尺寸、面积、地板等相关属性 |
| 家具 | 名称、尺寸、旋转，以及实际支持的外观与对象操作 |
| 墙体 | 现有墙体属性及门窗相关入口 |
| 门 / 窗 | 已有尺寸、位置、方向等字段，不显示内部对象 ID |

P0 允许复用现有门窗与房间弹窗：右栏展示选中对象摘要、相关操作和明确的编辑入口，不要求一次改成全部内联表单。先迁移现有字段、分组与操作，再做交互增强。若当前版本不能在画布直接选中某类对象，保留可理解的列表选择方式；不为实现“点中墙”而重写命中检测。

面积、材料估价、工程统计不再默认占据属性栏。确需保留的现有能力放入 `Project details` 或 `Advanced`，不要直接删除已有逻辑。

**验收：**

- [ ] 属性面板内容随真实选中对象变化，不出现上一件家具的残留值。
- [ ] 内部 ID、开发调试字段不出现在普通用户界面。
- [ ] 删除仅作用于当前对象，不与清空全房间混淆。
- [ ] 改值继续调用原有更新流程，撤销行为不退化。
- [ ] 面板收起只影响 UI，不偷偷取消选择、重置尺寸或删除对象。

### UI-060｜画布视图与工具入口整理

**目的：把常用视图操作放到画布附近，让模型而非按钮成为中心。**

在画布上方使用清晰的 `2D Layout / 3D View` 切换。缩放、已有适配视图能力、测量与视图设置放在画布角落的紧凑工具条。

3D 中直接显示 `Orbit / Walk` 切换；2D 中贴墙吸附放在编辑工具附近，状态可见。相机角度、墙体显示、房间名显示、家具显示和灯光等进入 `View options`，仅在适用的视图出现。

操作帮助改成可关闭的轻提示或帮助入口。原有顶部大段旋转说明、底部技术说明不持续占据画布。

**本轮限制：** 不强制改变现有项目默认打开的 2D/3D 模式，不新增相机自动取景算法，不新增遮挡墙体判断算法。已有能力可以换入口和更合理的显示；不存在的能力记录为后续任务。

**验收：**

- [ ] 当前处于 2D 还是 3D 一眼可见，切换不重置家具布局。
- [ ] 3D 专属设置不在 2D 模式中误导性显示。
- [ ] 现有墙体显示能力可达，名称与实际效果一致。
- [ ] 浮层不拦截整个画布的点击和拖拽事件。
- [ ] 收起工具菜单后，焦点与鼠标交互正常恢复。

### UI-070｜英文文案、单位与信息清理

**目的：完成界面表达的一致性，而不是通过换皮修改真实空间数据。**

优先检查英文模式下的导航、工具提示、字段、错误、确认弹窗和空状态。用户自己取的中文房间名不能被自动翻译或删除。

界面语言与长度单位独立。现有项目的单位设置优先，不因切到英文就强行改项目单位，更不能通过显示取整回写真实尺寸。

卡片尺寸可以用更短的显示格式；属性输入必须保留当前支持的准确精度与单位。床的公制名称不能不核对实际尺寸就直接改成 Queen / King。

人民币示例估价从默认主面板退出，不直接换成美元符号伪装成本地真实报价。

**验收：**

- [ ] 英文模式的系统文案没有明显中英文混杂，用户自定义内容例外。
- [ ] 不显示开发 ID、日志、调试字段。
- [ ] 切换语言不改变单位，切换单位不改变几何数据。
- [ ] 英制 / 公制往返显示后，未编辑对象的原始尺寸与位置保持不变。
- [ ] 显示取整与真实值区分清楚；不能把近似值当精确值回写。

### UI-080｜状态反馈、危险操作与基础可访问性

**目的：让界面不仅看上去统一，也能说明现在发生了什么。**

对实际存在的异步操作展示加载、成功与失败。对于同步本地动作不强加虚假的等待动画。错误应说明可以采取的动作，并保留用户未完成的输入。

清空家具、删除房间与删除单个物体分开命名。不可恢复的破坏性操作要确认；已有可靠撤销的日常删除不必每次弹窗阻断。

按钮和字段使用语义正确的元素；图标按钮有可访问名称；键盘焦点可见；菜单和弹窗能用键盘操作并正确返回焦点。文本输入时不能由全局 Delete、方向键等快捷键误操作场景。

**验收：**

- [ ] 清空操作明确说明会清空什么，不使用含糊的 `Clear all` 处理不同范围。
- [ ] 没有“失败但显示成功”“未保存却显示 Saved”的状态。
- [ ] 每个常用图标按钮可通过 tooltip 或可见标签理解，并有可访问名称。
- [ ] Tab 焦点顺序合理；Esc 关闭当前浮层，不意外删除场景内容。
- [ ] 输入框中的删除、方向键和文字选择不会触发场景级快捷键。
- [ ] 文字对比度与目标点击区域按第 11 章检查。

### UI-090｜视觉、功能与数据回归验收

**目的：让新版 UI 可以替换旧版，而不是交付一个漂亮但损坏的编辑器。**

从 UI-000 开始持续回归，而非到最后才补测试。采用相同项目数据、相同窗口尺寸和尽量相同相机角度进行前后对比。

复用当前已有测试工具。没有自动化条件时，至少完成有步骤、有结果记录的手动回归；不能把“理论上应该能用”写成“已通过”。

**验收：**

- [ ] 第 12 章的 P0 场景完成并有记录。
- [ ] 没有新出现的场景丢失、单位漂移、选中错误或操作入口缺失。
- [ ] 完成主要视口的新旧截图对比和异常状态检查。
- [ ] 无新增阻断性控制台错误、重复监听或重复渲染实例。
- [ ] 当前工程的构建、类型检查、测试按实际可用命令执行并记录结果。
- [ ] 未执行的项目标为未执行，并说明原因，不写“全部通过”。


### UI-095｜分阶段任务测试与卡点修正

建议安排 3～5 位没用过当前网站的试用者，给任务而不是讲解菜单：新建房间方案、放家具、改尺寸、找门窗设置、切换视图、找到已有文件操作。

这只是发现交互卡点的小规模测试，不用于证明市场需求或付费转化。记录入口找不到、名称误解、操作后不知道发生了什么等具体问题，再安排修改。

**验收：** 输出实际观察与调整记录；不以“看起来更欧美”作为唯一评价；不因个别意见立即扩展为新业务功能。


M1 后进行首次简短任务测试，M3 前复测“输入房间—放家具—改尺寸—测余量—保存并恢复方案”。重点检查用户是否理解新建会替换当前方案，以及是否能找到单位和视图操作。真实试用者不可用时先记录内部任务走查，将用户试用明确标为未执行，不能声称已获用户验证；是否接受该交付限制由产品负责人决策。

## 7. P1 详细任务

### UI-110｜家具本地搜索与分类体验

在现有家具目录上做前端筛选，不引入外部商品检索接口。搜索名称与已有分类，必要时增加少量明确的显示层关键词映射。

搜索范围应准确表述为当前家具库，而不是互联网商品。无结果时显示 `No furniture found`，允许清空搜索或切回全部分类。

**验收：** 输入、清空、切换分类和空结果正常；筛选不改变原始家具数据；结果卡片仍调用原有添加逻辑；搜索时不重建 3D 场景。

### UI-120｜家具缩略图与卡片质量提升

先整理已有资源，统一背景、缩放和留白。具备现成预览渲染能力时可以复用，但不为每张卡片创建常驻 WebGL 场景。

本轮不为家具美化改动模型几何。预览应与实际模型一致，不用随机实拍图或 AI 家具图冒充可放置对象。

**验收：** 图片不拉伸、不裁掉主要家具；资源加载失败有备用显示；长列表不会因预览明显拖慢编辑；名称与尺寸层级仍清晰。

### UI-130｜尺寸、房间与门窗表单精修

基于已经存在的字段和格式化能力优化输入布局。房间尺寸、家具尺寸和门窗位置采用各自清晰的分组，不把所有数字塞成一长列。

分开的 ft / in 输入框只有在能可靠调用现有单位转换和校验逻辑时实施。否则先保留当前有效输入方式并改善标签，复杂解析器另列任务。

门窗距离应明确测量基准。可用当前已有定位信息标出基准墙或墙角；没有足够数据时，不添加看似精确但无法解释的示意图。

**验收：** 空值、非法字符、超范围值不会破坏场景；未完成的输入不会被自动替换成 0；确认和取消行为明确；不改变几何算法或精度。

### UI-140｜窄屏、触控与键盘细节增强

完善单侧栏、抽屉和关闭后的焦点恢复。窄窗口下先保护画布和必要操作，再收起文字较长的低频工具。

对于画布中的拖动动作，盘点已有数值编辑、方向调整、点击放置等替代操作。不存在替代方式时列出具体缺口，不能把键盘操作直接等同于已经满足“单指针无需拖动”的要求，参见 [R4]。

**验收：** 窄屏无整页横向溢出；抽屉可关闭且焦点正常；触控目标不依赖 hover；现有键盘和非拖动操作仍可用；没有新增无从退出的遮罩。

### UI-150｜视图与灯光设置面板精修

将现有相机、墙体、标签显示和灯光设置整理成少量清晰分组。仅根据实际能力提供名称与说明，保留原值与行为。

3D 设置面板可分为 `Camera`、`Visibility`、`Lighting`。不因命名好看而将效果不同的多个开关错误合并。

**验收：** 每个选项对应真实效果；选择状态与画布同步；切换 2D/3D 后设置不会异常丢失；不存在未实现的高级效果占位。

### UI-160｜已有文件 / 导出流程的视觉统一

这是条件任务：UI-000 确认项目已有文件保存、导入或导出时才实施对应部分。

统一已有弹窗、格式选择、文件名、进度与错误信息。只有已经生成真实预览时才展示预览；只有确实输出图片时才称为图片导出。

**验收：** 文件格式、扩展名和按钮文案一致；错误可理解且不丢当前项目；保留旧版本能正常读取的兼容性；不加入收费报告、支付、分享或云存储的新实现。

若当前没有相关能力，将任务标记为 `N/A：当前版本无对应功能`，而不是创建一个不能工作的入口。

## 8. P2 任务

### UI-210｜轻量动效与视觉打磨

只在布局和功能稳定后添加少量 hover、菜单展开和面板切换反馈。建议动画约 120～180ms，并尊重减少动态效果的系统偏好。

不要为了侧栏平移动效，让高成本画布持续重建或让场景命中区域与视觉位置不同步。复杂情况优先选择无动画切换。

**验收：** 不阻塞点击、输入与撤销；不通过夸张弹跳或发光制造科技感；低性能设备和减少动态效果模式中仍可正常使用。

### 10.1 英文命名建议

| 中文用途 | 英文建议 | 注意事项 |
|---|---|---|
| 房间 | Room | 左侧标签 |
| 家具 | Furniture | 不写 Furnitures |
| 新建房间方案 | New room plan | 当前动作替换整个项目；提交按钮用 Create and replace，不用 Add room |
| 搜索家具 | Search furniture | 仅搜索当前实际目录 |
| 2D 平面 | 2D Layout | 与 3D View 成对出现 |
| 3D 场景 | 3D View | 不是渲染报告 |
| 属性 | Properties | 也可直接用对象名称作为标题 |
| 宽 / 深 / 高 | Width / Depth / Height | 与当前数据维度含义核对 |
| 长度 | Length | 不将 Length 与 Depth 随机混用 |
| 旋转 | Rotation | 显示单位或可理解的方向 |
| 房间面积 | Room area | 明确面积而非楼面总面积等其他概念 |
| 门 / 窗 | Door / Window | 类型和动作区分清楚 |
| 复制 | Duplicate | 仅在实际支持时展示 |
| 删除家具 | Delete item | 针对当前对象 |

| 清空项目全部家具 | Clear all furniture | 确认内容中再次说明范围 |
| 视图设置 | View options | 画布显示与相机入口 |
| 适配视图 | Fit view | 仅在实际有此能力时展示 |
| 本地保存成功 | Saved on this device | 仅基于真实本地保存成功 |
| 保存失败 | Couldn’t save changes | 提供可执行的下一步 |

### 10.2 尺寸显示规则

尺寸至少区分三个层面：模型内部真实值、当前编辑输入值、目录卡片摘要。

| 层面 | 规则 |
|---|---|
| 内部真实值 | 使用原有存储单位与精度，UI 改造不迁移 |
| 属性编辑输入 | 使用原有可靠解析 / 格式化能力，保留必要精度，单位明确 |
| 卡片摘要 | 可以简化呈现；近似显示必须可识别，不能回写真实值 |
| 面积摘要 | 可沿用当前精度或统一显示策略，但不改面积计算逻辑 |
| 文件输出 | 若已有导出，核对其单位与界面一致；不是仅更换页内文字 |

例如，家具卡片可显示 `W 72 in × D 36 in`，前提是对应真实值就是这些尺寸。它只是格式示例，不是要求把所有模型取整到整数英寸。

当现有真实尺寸为公制且不对应美国床型标准时，先使用中性家具名称与准确尺寸，不能只为本地化擅自冠以某个标准床型名称。

### 10.3 保存与导出的真实状态

保存状态不能从“用户刚点了保存按钮”推断成功。应复用实际成功或失败结果。

若只有手动保存，界面不能暗示自动保存；若只有设备本地保存，不能暗示登录账号后跨设备可用；若没有支付体系，不展示已经解锁的付费权益。

## 11. 可访问性与交互质量基线

本节是本轮 UI 质量要求，不等于完成整个应用的 WCAG 合规认证。

### 11.1 文字与焦点

普通文字以至少 4.5:1 对比度为检查基线；WCAG 对符合定义的大号文字有 3:1 的例外规则。小号辅助文字不能为了“高级感”变得难以阅读，参见 [R1]。

键盘可操作的控件需要可见焦点；不能简单用 `outline: none` 去掉焦点而不提供替代样式，参见 [R3]。

### 11.2 点击区域

本项目采用常规控件高 40px、独立图标按钮点击区域 44×44px 的设计目标。这是本项目的易用性选择，不是把 44px 误写成 WCAG 2.2 AA 的统一最低要求。

WCAG 2.2 的目标尺寸最低要求涉及 24×24 CSS 像素以及间距、等效操作、行内目标等例外，具体参见 [R2]。视觉图标可以是 18～20px，但点击区域不要跟着缩到同样大小。

### 11.3 拖动与替代操作

检查是否已有数值输入、点击后放置、按钮调整等无需拖动的单指针替代方式。仅增加键盘快捷键，不自动等于满足拖动替代要求；相关标准与例外参见 [R4]。

不存在相应能力时记录清楚，区分“UI 外壳已改造”与“画布交互缺口尚未补齐”，不对外宣称全面无障碍。

### 11.4 基础交互检查

- [ ] 字段有可见标签，错误信息与对应字段关联。
- [ ] 图标按钮有可访问名称，tooltip 不成为唯一可触控说明。
- [ ] 弹窗打开时焦点进入，关闭后回到触发位置。
- [ ] 菜单和非模态浮层不会把用户永久困在键盘焦点中。
- [ ] `Escape` 优先关闭当前弹层；输入期间不触发场景危险快捷键。
- [ ] 缩放和高对比度等情况下，主要工具不被遮住。
- [ ] 使用颜色区分状态时，同步提供文字、图标或边界变化。

### 12.3 项目数据不变的判定

仅打开新 UI、切换面板或切换显示单位，不应改变房间尺寸、家具真实尺寸、位置、旋转、门窗几何和对象关联。

### 12.4 性能与资源

记录同一设备、相同项目、相同视口的改造前后表现。重点关注拖拽流畅度、视图切换、家具目录滚动，以及打开设置时是否引起场景重建。

不将固定帧率写成未经验证的跨设备承诺。出现明显回退时检查重复事件监听、重复渲染循环、每卡片 3D 实例、大量阴影和不必要的状态联动。

### 12.5 浏览器验证范围

优先验证实际目标用户使用的桌面浏览器。首轮至少记录在 Chromium 系浏览器与 macOS Safari 中的实测情况；有条件再补 Firefox。使用执行时实际安装版本，不在文档里虚构浏览器版本或声称未测试的环境已兼容。

### 13.2 实际接入约束与状态归属

- `src/ui/room-editor.js` 的新建动作调用 `createRectangleProject` 并替换项目，必须保留替换说明、备份入口和撤销；不扩展为多房间建模。
- `src/viewer3d/viewer.js` 当前生成房间列表。迁移到公共 UI 层后由现有房间数据生成，2D 不依赖 Three.js 加载；列表选中调用现有选择动作，3D 定位单独调用相机接口，避免两个模块同时写列表。
- `src/core/editor-state.js` 已有 `ui.sel`，复用家具、房间、墙和门窗的选择语义；属性面板与结构区合并展示时不得创建第二套实体或相互覆盖。
- 2D / 3D 已通过 `src/ui/lifecycle.js` 的 ResizeObserver 观察画布。复用现有机制，验证容器尺寸与命中，不再建立重复监听；不强制在每次侧栏变化后 Fit 或重置相机。
- `src/ui/property-panel.js` 与 `src/ui/room-editor.js` 存在 innerHTML 重绘。输入期间保留草稿、焦点、光标及校验错误；仅更新需要变化的区域。对象删除、项目替换时明确结束失效草稿，不向新对象回写。
- `src/ui/furniture-library.js` 拖放已有浮层排除规则。新增画布工具条、菜单与设置浮层须统一排除放置和场景命中，避免点按钮误选对象、拖到菜单下仍放置家具。浮层外画布保持可操作。


| 状态 | 本轮处理 |
|---|---|
| 房间、家具、门窗真实数据 | 留在现有业务状态中 |
| 当前选中对象 | 复用现有选择状态，不创建冲突来源 |
| 当前左侧标签、展开菜单、侧栏显隐 | 可以作为 UI 状态整理 |
| 当前单位、语言 | 优先复用现有设置机制；不借机迁移业务数据 |
| 保存与导出状态 | 基于现有真实操作结果，不编造成功 |
| 相机与视图状态 | 复用当前机制，不因新组件挂载反复重置 |

## 最终决策

**先把现有编辑器做得清楚、统一、好操作，再考虑增加更多功能。**

本轮的成败不取决于做出了多少新菜单，而取决于：用户是否更容易找到已有功能，页面是否真正形成统一的视觉层级，以及原有房间与家具编辑能力是否被完整保留下来。
