## 本批目标与实施顺序

1. **建立真实基线。** 原生操作正常保存 / 刷新、存储拒绝 / 配额失败、损坏 v2、导入覆盖、新项目 / reset、两窗口同源编辑；记录复现、优先级、影响、截图和存储前后差异。先确认问题存在，再修复。
2. **准确保存状态与失败恢复。** 区分当前已提交修订与最后成功持久化修订；初始化能说明恢复来源。保存失败后保留内存工程与可操作的 JSON 备份 / 重试入口，后续成功时反馈恢复。避免每次更新重复弹窗。无需新增异步存储或无意义的 Saving 动画。
3. **覆盖前保护。** 有效导入、新项目、恢复示例使用一致的替换保护：可先导出当前工程、继续替换或取消。明确会替换的范围；取消不改模型、选择、单位、历史和草稿。自动保存成功仍不代表被替换的旧工程有独立备份；但不要给普通移动或已保存页面退出添加重复确认。
4. **损坏数据恢复。** 提供可发现的原始损坏数据导出 / 恢复选择；以用户明确选择为边界，不静默回退或覆盖。recovery 备份失败不得导致原数据丢失，不能报告虚假的备份成功。保留旧键和现有格式规则，不擅自清理 recovery key。
5. **多窗口最小冲突保护。** 同源另一窗口写入时，发现差异并阻止无声覆盖，提供保留本窗口并导出、读取另一版本或明确覆盖的操作；不实现自动合并。先复现，依据实际写入顺序实施最小方案。不同 origin / 浏览器 / 设备的数据彼此独立，说明跨设备通过 JSON 迁移。
6. **完整复测。** 共用生产逻辑验证 Jacobsen、CMU、修正 Plan F 和斜切边界。使用区、referencePlan、obstacles、墙段、门窗、单位偏好和精确浮点尺寸均保留；几何 / 保存逻辑不能按测试户型名称硬编码。

离页保护仅用于确有未持久化的已提交改动；浏览器离页确认不能替代备份。未提交字段草稿或进行中的拖动需明确提交 / 放弃规则，不能误报已保存，也不能擅自把无效输入保存。更换项目时已有异步读取防护、view transition 禁用、撤销一致性与组件 dispose 规则必须保留。

| 场景 | 验收条件 |
|---|---|
| 正常保存、刷新、撤销 / 重做、单位切换 | 状态对应真正成功的当前数据；mm 精度不变。正常成功保存后退出没有额外确认。 |
| setItem 拒绝 / 配额失败，再恢复存储能力 | 已存副本不变、内存工程仍可编辑和实际下载；重试成功后状态恢复，刷新读取正确修订。 |
| 损坏 v2；同时存在有效 v1 / legacy | 不静默回退，不覆写原文；原文实际下载与用户恢复路径通过，备份写失败也不破坏原文。 |
| 合法 / 无效 / 超大 JSON、迟到读取 | 无效输入不替换；合法替换可以备份并取消；读取期间修改继续受到修订保护。 |
| New project / reset、替换撤销 | 取消工程和草稿保持；确认后生成目标工程，Undo / Redo 正确恢复，刷新后保存一致。 |
