## 2. 背景与已核实的问题

当前不是完全单文件：T01 已抽出项目格式及户型模板。但 `index.html` 仍有约 2653 行，包含 CSS、静态界面、状态、2D 渲染和交互、3D 场景与模型、文件操作及多语言。

主要耦合点：

1. `mutate()`、`commit()` 同时关联修改、历史、保存和整体渲染。
2. `state`、`ui`、`view` 及几何别名被多个功能直接读取或修改。
3. 2D/3D 通过 `window.View3D`、`window.select()`、`window.closeDrawers()` 等全局桥接。
4. `renderPanel()` 和面板绑定函数把 HTML 生成与事件处理放在一起。
5. `buildFurniture()` 接近 500 行，与材质和几何帮助函数相互依赖。
6. 数据测试通过正则从 HTML 取脚本，再用 `vm` 执行前半段以获得默认项目，容易被文件结构变化破坏。
7. 全局脚本和 module 脚本混用；直接搬进 ES Modules 会改变变量可见性、初始化顺序和 `window` 暴露行为。

这些是结构性维护问题。不要据此宣称当前所有操作都有功能缺陷；先复现并记录实际行为。

## 5. 依赖与状态规则

### 5.1 数据流

```text
工具栏 / 属性面板 / 2D 或 3D 交互
                ↓ 调用明确的修改操作
        项目 store + 一次操作的历史记录
                ↓ 发布变更
     2D 更新 / 3D 更新 / UI 更新 / 保存服务
```

`main.js` 负责组装。UI 不直接操作 3D 内部对象；2D 不引用 3D 内部实现；3D 不调用 UI 模块中的全局函数。需要选中对象、改变视图或关闭侧栏时，通过注入的回调或明确应用接口执行。

### 5.2 状态归属

| 状态 | 归属与约束 |
| --- | --- |
| 可导出的项目数据 | store 唯一持有，包括几何、家具、房间设置、测量及文件已有偏好 |
| 选中、工具、拖动中的临时信息 | editor state；不新增到项目文件 |
| 2D 缩放/平移、3D 相机和动画 | 对应视图拥有；不写入实际尺寸，不擅自扩大持久化范围 |
| Renderer、DOM、材质、纹理、事件监听器 | 对应组件/视图生命周期管理；不得进入 JSON 或历史快照 |
| 保存错误与导入结果 | service 返回明确结果，由应用/UI 展示；核心模块不调用 `alert` 或 `confirm` |

渲染器读取项目，修改通过 store 或明确事务执行。拖动预览允许持续刷新，但一次完整拖动只形成一条撤销记录；取消拖动应恢复操作前结果。不要每次 `pointermove` 都生成历史或重复创建监听器。

变更通知必须携带当前状态或可获取当前状态，避免订阅闭包永久引用导入之前的旧项目。不要简单把全部全局变量塞进一个巨大的 `context` 对象后视为解耦完成。

### 5.3 接口建议

采用少量、可读的接口即可，例如：

- Store：`getProject()`、修改/事务方法、`replaceProject()`、`undo()`、`redo()`、`subscribe()`。
- 视图：`createEditor2D(...)`、`createViewer3D(...)`，返回 `update()`、必要交互接口及 `dispose()`。
- UI：接收 DOM 容器、只读状态和操作回调，返回 `update()`/`dispose()`。
- 文件服务：先解析和验证，成功后由应用层替换项目；需要旧模板确认时返回明确状态，由 UI 获取确认。
- 存储服务：明确成功/失败及错误，不自行修改项目几何。

以上名称不是强制 API。不要为将来所有场景设计通用事件总线、插件系统或复杂命令类层级。

### 5.4 模块与加载

浏览器与 Node 的模块方案必须统一。可使用 `.js` 加最小 `package.json` 的 `"type": "module"`，同步把测试改为 ESM；也可采用 `.mjs`。不需要因此新增运行依赖或打包器。若新增 `package.json`，`npm test` 可作为 `node --test` 的便捷入口。

保留 Three.js 的版本及 import map。2D 初始化不应因 3D CDN 失败而完全停止：在应用初始化边界隔离 3D 模块加载，失败后有明确提示，2D 和项目文件操作仍可使用。不要在纯数据模块中导入 Three.js。

## 9. 重点风险与处理方式

| 风险 | 处理要求 |
| --- | --- |
| ESM 循环依赖/初始化先后 | 数据与 core 不依赖 UI；由入口组装；避免通过顶层副作用互相启动 |
| 模块顶层失去旧全局可见性 | 逐项登记隐式依赖并显式传入，不能批量搬文件后靠重新挂到 window 补救 |
| CDN 异常阻断全部应用 | 把 3D 加载与 2D/文件服务初始化分开 |
| 多份项目状态产生漂移 | 一个 store；视图持有运行时状态，不能再各自维护可编辑项目副本 |
| 保存订阅形成递归通知 | 明确保存和 metadata 更新边界；渲染不修改项目 |
| 快照混入运行时对象 | 历史与导出只处理纯项目数据，排除 DOM、Three.js 对象和函数 |
| 事件重复绑定/资源泄漏 | 使用组件销毁接口，对应取消监听、观察器和动画帧，资源有明确所有者 |
| CSS 抽离后相对路径或层叠变化 | 保持规则顺序，检查资源路径、窄屏和图层覆盖关系 |
| 改进架构时扩展了产品范围 | T02/T03 需求登记接口接入点，实际新功能留到后续任务 |
