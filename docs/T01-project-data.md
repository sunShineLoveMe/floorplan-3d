## 结果与范围

基于 `a03136c`，分支 `feat/project-data-t01`。原有 SVG/Three.js 渲染器继续使用；项目文件现在携带户型几何，不再依靠接收方的固定示例还原。

- `sample-template.js`：原三室两厅两卫的几何、门窗高度、过梁、尺寸链、视图范围及漫游起点。
- `project-data.js`：不依赖 DOM 的项目创建、格式验证及显式旧格式迁移。
- `index.html`：项目读写、模板加载、撤销恢复和 2D/3D 数据绑定。
- `tests/fixtures/custom-project.json`：3048 × 3657.6 mm 的独立卧室，含窗、812.8 mm 门和旋转床，用于确认没有残留示例建筑。

自定义房间创建 UI、英制显示/输入、家具高度编辑 UI、冲突检测、收费都不在 T01 范围内。

## v1 文件约定

| 字段 | 含义 |
|---|---|
| `format` / `version` | `floorplan-3d` / `1`；未知格式及版本拒绝导入 |
| `id` / `name` / `createdAt` / `updatedAt` | 项目标识、名称及 ISO 时间 |
| `units` | 内部 `mm`；`display` 保存 `metric` 或 `imperial` 偏好，T03 才实现英制界面 |
| `geometry.rooms` | 稳定房间 ID、内墙净轮廓、默认名称/材质、标签位置、面积计入标记 |
| `geometry.walls` | 保留渲染器的 `[x0,y0,x1,y1,type]` 实体墙段矩形，类型 b/e/n/low；段 ID 为 `w` 加数组索引 |
| `geometry.windows` | `rect`、`sill`、`head`，均为毫米 |
| `geometry.doors` | 洞口 `rect`、铰点 `h`、关闭/开启单位方向向量 `c/o`、宽 `len`、洞口高 `height` |
| `geometry.slides` / `lintels` | 推拉门及额外过梁的矩形、方向/高度 |
| `geometry.height` / `origin` | 全局层高及 3D 坐标原点 |
| `geometry.bounds` / `dimensions` | 视图/导出范围及尺寸链；不重新推算并覆盖净轮廓 |
| `geometry.entry` / `walkStart` | 可选入口标注、漫游初始位置/朝向 |
| `rooms` | 按房间 ID 保存用户修改的名称和材质；与几何房间一一对应 |
| `furniture` | ID、类型、名称、宽深、中心位置、旋转、颜色；可选 `height` 为外包高度，3D 按该值缩放 |
| `layout` | 当前布局 ID 和名称；当前只支持一个布局 |
| `view` | 2D/3D 模式及 2D 图层/吸附偏好；不参与尺寸换算 |
| `demolished` / `measures` | 拆除墙段 ID 和测量端点 |

所有几何长度保留浮点毫米，不根据显示舍入写回。原家具没有统一的高度字段，缺省时继续使用该类型的原模型高度；已提供的高度会保存、恢复并应用于 3D。统一家具外包尺寸与高度编辑仍由 T04 完成。

本批保留**实体墙段**模型，避免重写渲染器。墙厚由矩形短边表示，门窗使用绝对洞口坐标。房间所属墙与门窗相对父墙的编辑关系需要在 T02 加入；不能直接重新排序/删去墙段而不迁移 `demolished` 引用。未来修改文件结构时递增版本并提供迁移，不复用 v1 悄悄改变语义。

## 保存和兼容策略

- 新数据使用 `floorplan-project-v1`；旧 `huxing-design-v1` 保留不动。
- 新格式先完整验证，再替换当前状态。未来版本、无效 JSON、无效尺寸、重复 ID、无效材质和悬空引用均不能覆盖当前项目。
- 无版本旧文件只有家具及房间设置，没有可靠模板身份。必须由用户确认它属于原始三室两厅两卫模板；取消即保持原状态。
- 确认后，先验证迁移结果，再下载原始文本为 `floorplan-legacy-backup.json`，然后加载新项目。磁盘原文件和旧存储键均不会改写。
- 读取失败的新版本地数据保持原样。用户随后编辑要保存时，先写入带时间戳的 recovery 键；备份失败则不覆盖原值。
- 保存异常给出失败提示；全套持久保存状态 UI 属于 T07。
- 导入可以撤销/重做，包含完整户型几何。历史记录仍仅保存在当前页面会话。
