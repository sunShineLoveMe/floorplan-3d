## 推荐第一版范围

先实现“一个账号拥有多个私有项目”，覆盖注册 / 登录 / 退出、会话恢复、项目列表、新建 / 打开 / 重命名、云保存、文件上传、版本恢复、删除及恢复、本地旧项目迁移。用户仍可不登录进行本地编辑；登录后明确选择将当前本地项目保存为云项目。

采用 **现有前端 + 薄业务 API + PostgreSQL + 成熟认证服务 + 私有对象存储**。认证组件处理身份，业务 API 处理项目权限、输入校验、原子版本更新和资产归属；客户端不掌握数据库管理员凭据。数据库 / 认证 / 对象存储具体供应商在开始接入时确定，本评估不假定用户已安装插件的种类或连接状态。

无需在此阶段把房间、门窗和每件家具拆成独立数据库表。项目快照作为 `jsonb` 保存，项目名称、所有者、修订号、时间等作为关系字段。PostgreSQL 支持 JSON 与关系结构共存；整份文档更新锁定整行，因此应限制快照大小并控制写入频率。[PostgreSQL JSON 文档](https://www.postgresql.org/docs/current/datatype-json.html)

| 数据 | 第一版存放方式 |
| --- | --- |
| 用户资料 | `profiles`，关联认证服务的稳定 user ID；不另存明文密码 |
| 项目 | `projects`：服务端项目 ID、`owner_id`、名称、`schema_version`、`revision`、快照、服务端时间及删除状态 |
| 可恢复版本 | `project_versions`：项目 ID、版本号、快照及资产引用；设置保留策略，不把每次拖动或所有 UI 偏好都存成永久版本 |
| 原始 PDF / 图片、标定后的参考图 | 私有对象存储；`project_assets` 记录项目归属、用途、object key、类型、大小及 hash |
| 本地未同步草稿 | 按用户 / 云项目分隔的浏览器缓存；较大数据使用 IndexedDB；保留 JSON 离线备份 |

当前 `referencePlan` 只接受内嵌 data URL。抽离文件时需要显式云资产封装 / 加载适配，不能直接把该字段改成网络 URL 绕过校验；离线 v2 JSON 导出仍需可独立回导。可复用的公开样板户型与用户私有项目分开：从样板创建用户项目副本，原测试 JSON 的项目 ID 不作为权限凭据。

## 权限边界

第一版只需要游客和项目所有者的业务权限，不必先开发组织 / 团队、邀请协作或复杂角色后台。

| 身份 | 本地编辑 | 云端操作 |
| --- | --- | --- |
| 未登录游客 | 可以，本地草稿 | 不能访问私有项目 / 文件 |
| 已登录的项目所有者 | 可以 | 可操作自己的项目、资产及版本 |
| 已登录的其他用户 | 可以编辑自己的项目 | 不可读取、修改、删除别人的项目，也不可取得其文件下载权限 |
| 未来 editor / viewer | 后续明确设计 | 仅授权项目范围；不通过“知道项目 ID”自动获取权限 |

每次 API 和文件签名请求都核验身份、资源归属和操作权限；用户 ID 来自可信会话，不能信任上传 JSON 或请求体中的 `owner_id` / `role`。项目资产、版本恢复、上传完成确认、删除和恢复同样受保护。规则默认拒绝，前端隐藏按钮不能替代服务端检查。[OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

可用数据库 RLS 作为纵深保护，但应核对数据库角色：表所有者 / 绕过 RLS 的角色与普通应用连接不同，不能假设开启 RLS 后所有访问都自动隔离。[PostgreSQL Row Security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 保存和迁移必须补齐的实现

1. **同步本地保存与异步云保存分离**：现有 `save-recovery.js` 每次已提交变化就同步保存。新增保存协调器，只上传 committed snapshot，防抖、串行发送；明确显示本地已保存 / 云端待同步 / 同步中 / 云端已保存 / 失败 / 冲突。
2. **服务端原子冲突保护**：使用 `revision` 或等效条件更新，服务端以当前修订号比较并在同一事务内递增。旧修订提交返回冲突，保留本地草稿并提供另存副本 / 读取云版本；不能照搬本地字节比较或只按客户端 `updatedAt` 覆盖。
3. **应答对应具体提交**：发送期间若继续编辑，旧请求成功不能把新改动标成已同步；先保留该请求确认的快照，后续继续上传。跨项目 / 账号切换使旧请求失效或忽略迟到应答，防止错写。
4. **身份与编辑数据隔离**：云项目 ID、`owner_id`、权限和 revision 不进入用户可导入的授权字段或 Undo 栈；客户端项目 `id` 和服务端资源 ID 显式映射，导入新副本不能覆盖他人的同名 / 同 ID 项目。
5. **账户隔离和本地迁移**：现单一 localStorage 键不能原样作为所有账号的缓存。退出 / 换账号先处理未同步草稿，清理当前账号内存视图和授权；另一个账号不能自动打开前一个账号项目。旧本地项目需审查后显式创建云副本，原 JSON 和本地备份保留。
6. **服务端再校验**：复用无 DOM 的项目数据校验和 catalog 约定，另加请求体、上传文件大小 / 类型、项目配额和速率限制。校验失败不写项目，文件上传失败不产生“已完整保存”的状态；多步骤采用 finalize / 清理孤立上传等机制。
7. **生产服务边界**：部署只发布前端所需资源；开发服务默认可访问仓库文件，不直接对公网开放整个仓库。数据库备份、对象存储恢复、会话和权限测试属于后端交付，不以数据库连接成功代替验收。
